# 庁内照会・回答集約 PoC

国等から届くExcel調査票（原票）への庁内回答について、**とりまとめ部署と回答部署の双方が「今までより楽」と感じられるか**を試すための、操作できる小規模なWeb試作です。Issue [#15](https://github.com/YanTKYS/poc-lab/issues/15)。

- 公開先：<https://yantkys.github.io/poc-lab/inquiry-workflow/>（main へのマージ後に公開）
- 設計資料：[poc-docs / inquiry-workflow](https://github.com/YanTKYS/poc-docs/tree/main/proposals/inquiry-workflow)（特に `02-ux-screens.md`）
- Excel入出力の技術検証（#14）：[EXCEL.md](EXCEL.md)
- 評価の手順と記録表（S1〜S8）：[EVALUATION.md](EVALUATION.md)

> **公開PoC・架空データ専用です。** 実在の調査票・職員情報・個人情報は入力しないでください。入力内容はブラウザの中（localStorage）だけに保存され、外部へは送信しません。本番利用・庁内運用・データ保管には使えません。

## 5分で一通り試す

1. 公開先を開き、「架空の原票を読み込む」を押す（4シート・入力セル62個の架空様式）。
2. **① 割当て**：表で範囲をドラッグして選び、右の担当課を押す。残りは「デモ用ショートカット」→「例の割当てを適用する」（9範囲を9操作）。
3. **② 依頼**：締切を入れて「回答の受付を始める」。依頼文が出る（**デモ専用**。コピーを試せるだけで、実際の依頼には使えず、送信もしない）。
4. 右上で **回答部署** に切り替え、課を選んで回答し、「提出前の確認へ」→「提出する」。施設管理課の表には、Excelの範囲を貼り付けられる。
5. **とりまとめ部署** に戻り、**③ 進捗・集約** の「デモ用ショートカット」で残りの課を提出済みにする。どれかの項目を「差戻し」する。
6. 回答部署でその課を開くと、差戻しが一番上に出る。直して再提出すると解消し、とりまとめ側に履歴が残る。
7. ③ で複数課項目（問12・問13）の確定値を決める（合計・連結の候補を押して「この値で確定」）。
8. **④ 確認用Excel（ドラフト）** で書き込む内容を確認し、「確認用Excelを出力する」。自動照合の結果とダウンロードが出る（**デモの確認用ファイル。正式提出には使わない**）。

最初からやり直すときは、画面下の「最初からやり直す」を押します。

## 画面と操作

### とりまとめ部署

| 画面 | できること |
|---|---|
| 原票の登録 | 架空の原票、または手元の .xlsx（3MBまで）を登録。扱えない形式は理由を表示して登録しない |
| ① 割当て | 原票をシートごとに表で表示。入力セルの**候補**（ロック解除・入力規則あり・色付きの空欄）を色と文字で表示し、数式セルは「数式」と表示。ドラッグ／Shift＋クリック／行番号・列名・左上の角／番地の入力（例 `C5:D8`）で範囲を選び、担当課を押すと一括で割り当てる。複数課の項目、任意項目、入力不要、候補外のセルの追加、見出し・型・補足の修正もここで行う。原票のセルに**元からある文字・数値（「　年　月」等のひな形、記入例）は、担当課のチップと並べて表示**し、割り当てても消えず、原票も書き換わらない。**未割当ての項目は自課が回答する** |
| ② 依頼 | 課ごとの項目数、締切、受付開始、依頼文（共通リンク入り）のコピー。**デモ専用**（下記） |
| ③ 進捗・集約 | 課ごとの状態（未着手・作成中・提出済み・差戻し）と入力数。催促文・差戻しの連絡文のコピー（デモ専用）。回答の確認（注意のある項目だけ／すべて／課ごと）、項目単位の差戻し、軽微な修正（履歴に残る）、複数課項目の確定 |
| ④ 確認用Excel（ドラフト） | 書き込む件数・書き込まない件数（未提出・未回答・未確定など）・注意の件数と、その内訳を確認し、原票の複製に値を書き込んで出力。出力直後に自動照合し、問題があればファイルを渡さない。**未提出・未回答が残っていても出力できる**（途中経過の確認用） |

### 回答部署

| 画面 | できること |
|---|---|
| 課の選択 | 共通リンク（`#answer`）を開いて所属課を選ぶ。本番では所属から自動判定する想定だが、このPoCには認証がない |
| 回答 | **自課の項目だけ**を設問ごと（行ごと）に表示。数値・％・日付・選択肢・文章の入力欄、該当なし、原票での位置（周囲の抜粋）、補足。入力は自動で保存。誤りはその場で表示（数値・整数・下限などの入力規則、日付、選択肢）。数値の表は表のまま表示し、Excelの範囲を貼り付けられる（Enterで下へ、「-」で該当なし）。原票に元からある文字・数値（ひな形・記入例）は、入力欄の近くに「原票の記入例／既存値」として表示する（数値の表では欄の薄い文字）。**入力欄には入らず、入力済みにも数えない** |
| 差戻し | 未解消の差戻しを理由と一緒に一番上に表示。値を直すか、直さない理由を返答して再提出すると解消 |
| 提出 | 提出前の確認で、未入力・誤り・差戻しへの未対応を一覧（押すとその項目へ移動）。提出後は、取り消して修正できる |
| 回答一覧の印刷 | 課内確認用。従来どおり回覧・決裁に使う（決裁の仕組みは作らない） |

## 両部署にとっての改善点と新たな負担（仮説）

**実測はしていません。** 確かめ方は [EVALUATION.md](EVALUATION.md)。

| | 減ると見込む負担 | 新たに生じる負担 |
|---|---|---|
| とりまとめ部署 | 課別ファイルの作成（範囲の一括割当てに置換）、回収、未提出課の把握、転記、差戻し箇所の説明と再転記、複数課の回答の突き合わせ | 原票の登録と入力セル候補の確認、見出しの補正、割当てを先に決めきること、出力ファイルをExcelで確かめる手間 |
| 回答部署 | 担当箇所を探す、記入要領との往復、ファイルの保存・返信、差戻し時の開き直し、提出状況の確認 | 新しい画面に慣れること、課を選ぶ操作（認証がないため）、Excelで下書きして決裁する課での二度手間 |

**変わらないもの：** 依頼・催促・差戻しの連絡を送る手間（実運用では、同様の文面を既存のメール等で人が送る想定）、課内の確認・決裁、正式提出前のExcelでの確認。これらを「削減した」とは数えません。

## Excel連携（#14 の方式B）

- 原票は登録時のまま保管し、書き換えません。出力のたびに**原票の複製**へ、確定した値だけを書き込みます。
- 書き込むのは、**提出済みの課の回答**と、**確定した複数課項目**だけです。未提出・未回答・未確定の項目は書かず、原票のセルをそのまま残します（出力前確認に理由つきで表示）。
- **回答がなければ、原票の内容をそのまま残します。** 割り当てただけで原票の文字を消したり、空欄に置き換えたりしません（未回答のセルには書き込みを指示しません）。回答した（または「該当なし」を選んだ）セルにだけ、その回答を書き込み、原票の元の文字・数値は置き換わります。出力前確認の「書き込まない項目」に、原票のまま残る内容を表示します。
- 複数課項目の確定は、**担当課がすべて提出済みのときだけ**できます。確定値は、確定した時点の各課の回答と結び付けて記録し、あとで回答が変わる・提出が取り消される・差戻し中になると、**「再確認・再確定が必要」と表示して書き出しません**。
- 出力直後に、書いたセルの値と型、対象外のセル・数式・行・結合・入力規則・保護などが元のままかを自動で照合します（[EXCEL.md](EXCEL.md) の `verifyWriteBack`）。
- **非表示のシート**（`hidden`・`veryHidden`）は、入力セル候補の抽出・割当て画面・回答画面の対象にしません。割当て画面と出力前確認に「非表示のシートは、回答・割当ての対象にしていません」と対象外のシート名を表示します。非表示シートのセルは、他の表示シートの入力規則の選択肢の参照元としては読み取ります（例：`veryHidden` にした記入要領の選択肢を、表示シートの選択欄で使える）。**確認用Excelでは、非表示シートの内容・数式・書式・保存済みの計算結果・表示状態を1バイトも変えずに残します**（非表示→表示にもしません。出力直後の自動照合でも確かめます）。すべてのシートが非表示の原票は登録できません。非表示シートを編集する画面や設定はありません。
- 数式は書き換えませんが、保存されていた前回の計算結果は消します（Excelで開いたときに再計算させるため）。対象は表示シートだけで、非表示シートの数式は、保存済みの計算結果も元のままです（Excelで開くと再計算されます）。
- 「該当なし」は、文章の項目では文言「該当なし」（画面で空欄に切り替え可）、数値・日付・選択の項目では空欄として書きます。％の項目は、画面の 12.5 を原票には 0.125 として書きます。

### 制限（必ず読んでください）

- **このPoCが出力するのは「確認用Excel（ドラフト）」であり、正式提出には使えません。** Microsoft Excel での開封・再計算・保存、および提出先での受理は未確認です。方式Bは「条件付き採用」のままです。**このPoCの出力を「国への提出に実用に耐える」と判断する前に、Excel実機での確認が必要です**（[EXCEL.md](EXCEL.md) の「未確認」1・2）。画面の出力前・出力後にも、同じ旨を表示しています。
- 出力したファイルには数式の計算結果が入っていません。Excelで開くまで合計欄などは空です。
- 自動照合が保証するのはファイルの中身までです。見た目・再計算の結果・国側のエラーチェック欄は、Excelで開いて人が確認してください。
- 出力ファイル名は英数字（`<原票名>_preview.xlsx`、原票名が日本語なら `inquiry_preview.xlsx`）です。正式な提出ファイルと取り違えないよう、`_preview` を付けています。検証に使った Chromium では、日本語のファイル名を付けると「download」（拡張子なし）に置き換わったためです。

## 対応外・既知の制約

| 区分 | 内容 |
|---|---|
| 利用形態 | 1台の端末・1つのブラウザの中だけで動く。認証・権限・多端末の同時利用・データの共有はない。依頼文の共通リンクを別の端末で開いても、回答は共有されない。ブラウザのデータを消すと消える |
| 保存 | 原票（base64）と入力をブラウザの localStorage に保存する。容量が足りない場合（大きな原票など）は保存に失敗し、画面上部に警告、回答画面に「保存できていません」と表示する（その状態で再読み込みすると入力が失われる） |
| 範囲の指定 | 番地の直接入力は、表示中のシートの範囲内だけ受け付ける |
| 通知・連絡文 | 送信しない。依頼・催促・差戻しの文面はコピーできるが、**デモ専用**（冒頭に「【デモ専用・実際の依頼として送付禁止】」が付く）。1台・同一ブラウザの中だけで動き、別の端末でリンクを開いても回答内容は共有されないため、実際の依頼には使えない。メール送信・自動通知・共有の機能は作らない |
| 操作の記録（CSV） | フッターの「操作の記録をCSVで保存」は、**評価のための操作ログ**。回答データの書き出し・復元・バックアップ・部署間の引継ぎには使えない（それらの機能は作らない。本番化を検討するときの別課題）。何を数えているかは [EVALUATION.md](EVALUATION.md) の「数え方の定義」 |
| 非表示シート | `hidden`・`veryHidden` は対象外（上記）。**隠し列・隠し行は対応していない**（非表示の列・行にある入力セルも、候補として表示される）。ブラウザに保存済みの状態に非表示シートの項目が残っていたら、読み込み時に対象から外す（「非表示シートにあった N項目を…」と表示） |
| 原票 | .xls・.xlsm・パスワード付き・行を追加していく様式は対象外（登録時に拒否するか、割当て対象にならない）。3MBまで |
| 入力セル候補 | 「ロック解除」「入力規則あり」「色付きの空欄」だけで判定する。外れたら手で直す。**色付きで、ロック解除も入力規則もなく、ひな形文字が入っているだけのセルは、自動では候補にならない**（「色付きの空欄」は空欄が条件のため。見出しセルなどを誤って候補にしないため）。その場合は割当て画面で選んで「入力セルにする」を押す |
| 見出し | 同じ行の左側と、同じ列の上側の文字列から作る候補。複雑な見出し（多段の結合など）は外れやすい |
| 型・選択肢 | 表示形式と入力規則から推定。選択肢は入力規則のリスト（直接指定またはセル範囲）だけ。時刻・真偽値・書式付き文字列は扱わない |
| 入力チェック | 数値の整数・単一の下限／上限、日付、選択肢だけ。原票の他セルを参照する規則や、セル間の整合（合計の一致など）は確認しない |
| 表の表示 | 同じシートで2行2列以上の数値項目だけを表として表示。それ以外は設問ごとに表示 |
| 集約 | 複数課項目の候補は、数値は合計、文章は「【課名】回答」の連結だけ。確定は人が行う |
| その他 | 前回回答の表示、締切の自動催促、回答の一括取込（CSV等）はない。印刷は簡易な一覧のみ |

## 起動方法（ローカル）

リポジトリ直下で実行します。

```sh
npm ci
npm run build                     # dist/ を出力（fflate を vendor/ に同梱）
npm run serve                     # http://localhost:4173/poc-lab/inquiry-workflow/
```

テスト：

```sh
npx playwright install chromium   # 初回のみ
npm test                          # 画面の動作テスト（tests/inquiry-workflow.spec.js ほか）
cd inquiry-workflow && npm ci --ignore-scripts && npm test   # Excel入出力と業務ロジックのテスト（Nodeのみ）
```

CI：`pages.yml`（ビルドと Playwright）と `inquiry-workflow-tests.yml`（Nodeのテスト）が、PR と main への push で動きます。
