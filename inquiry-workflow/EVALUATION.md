# 評価の手順と記録表（S1〜S8）

設計資料 [04-poc-plan.md](https://github.com/YanTKYS/poc-docs/blob/main/proposals/inquiry-workflow/04-poc-plan.md) のシナリオ S1〜S8 を、**従来方式（Excel＋メール）と新方式（このPoC）で同じ内容**だけ行い、両部署それぞれの負担を比べるための手順です。

- **数値は実測したものだけを書きます。** この文書の記録欄は空欄のままです（作成者は実施していません）。
- 参加者は少人数を想定しており、統計的な結論は出せません。目的は、傾向とつまずいた箇所の把握です。
- 判断の基準は設計資料 04 §6 のとおり：**とりまとめ部署・回答部署のそれぞれで**、時間・操作回数・手戻り・迷いのいずれかに改善があり、ほかが悪化していないこと。片方だけの改善は成功としません。

## 準備

| 項目 | 従来方式 | 新方式（PoC） |
|---|---|---|
| 原票 | `fixtures/genpyo.xlsx`（架空） | 同じ原票を「架空の原票を読み込む」で登録 |
| 配布・連絡 | 実際のメール（テスト用の宛先） | 依頼文をコピーして、同じくテスト用の宛先へメール |
| 端末 | とりまとめ役・回答役がそれぞれのPC | **1台の端末で役割を切り替える**（PoCの制約）。役割を交代するときは、観察者が時計を止める |
| 記録 | 観察者が時間と操作を数える | 観察者が数える。PoC内の操作はフッターの「操作の記録をCSVで保存」でも確認できる（メール操作など外の作業は含まれない） |

- 新方式を始める前に、フッターの「最初からやり直す」で状態を消します。
- 順序の影響を減らすため、参加者の半数は従来方式から、半数は新方式から始めます。
- **新方式は操作説明なしで始めます**（説明が必要かどうか自体を見るため）。デモ用ショートカットは使いません。

## シナリオと手順

| # | 役 | 新方式（PoC）での操作 | 従来方式での操作 | 主に見ること |
|---|---|---|---|---|
| S1 | とりまとめ | 原票を登録 →「① 割当て」で範囲を選んで課を割り当て（割当て例は設計資料 01 §1）→「② 依頼」で締切を入れて受付開始 → 依頼文をコピーしてメールで送る | 課別に原票を分割・色分けしたExcelを作る（または全課に原票を送る）→ メールで配布 | 割当ての手間がExcelの分割・色分けより軽いか |
| S2 | 回答（市民課） | メールのリンクを開く → 課を選ぶ → 6問に回答 → 提出前の確認 → 提出 | 添付を保存して開く → 自課の箇所を探して記入 → 保存 → 返信 | 担当箇所を探さずに回答できるか。設問・入力欄の意味が分かるか |
| S3 | 回答（施設管理課） | 表の左上の欄に、手持ちのExcelの範囲を貼り付け → 問13 に回答 → 提出 | 原票の表に転記（またはコピー）→ 保存 → 返信 | 表のまとめ入力がExcelより不便になっていないか |
| S4 | とりまとめ→回答 | 「③ 進捗・集約」で施設管理課の「中央公民館 利用者数」を差戻し → 連絡文をコピーしてメール → 回答役が修正・再提出 → とりまとめ役が解消を確認 | 修正依頼のメールで場所を説明 → 回答役が開き直して修正・再送 → 再転記 | 差戻しに簡単に対応できるか。やり取りの回数 |
| S5 | とりまとめ | 進捗表で未提出の課を確認 → 催促文をコピーしてメール | 受信メールから未提出の課を調べる → 催促メール | 未提出の把握に迷わないか（送信の手間は両方式とも残る） |
| S6 | とりまとめ | 複数課項目（問12・問13）で各課の回答を見比べ、確定値を決める | 2課以上のExcelを開き、合算・連結して原票に書く | 集約に迷わないか |
| S7 | 回答（任意の1課） | 「回答一覧を印刷（課内確認用）」で上席に見せる | 記入済みExcelを印刷して見せる | Excelで下書きする二度手間が生じないか（**実際の決裁手順は再現できない**） |
| S8 | とりまとめ | 「④ 提出用Excel」で出力前確認 → 出力 → **Excelで開いて**確認 | 転記済みの原票をExcelで確認 | 出力前確認で迷わないか。出力ファイルに問題がないか |

**S8 の注意：** 出力ファイルを Microsoft Excel で開いたときの挙動は未確認です（[EXCEL.md](EXCEL.md)）。開けない・修復表示が出る・計算されないなどがあれば、その内容を必ず記録してください。

## まとめ方

| | とりまとめ部署 | 回答部署 |
|---|---|---|
| 時間・操作回数が減ったシナリオ | | |
| 増えたシナリオ（新たな負担） | | |
| 手戻り・迷いの変化 | | |
| 判定（設計資料 04 §6） | 改善あり／なし | 改善あり／なし |

両方とも「改善あり」で、Excel実機での確認に問題がなければ、実物（匿名化した照会Excel）での確認に進みます。どちらかが「なし」なら、その部署の画面・手順を見直すか、内製をやめる判断をします。
