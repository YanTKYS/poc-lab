# 庁内照会PoC ① Excel原票の無変更往復・セル値書き戻し検証

Issue [#14](https://github.com/YanTKYS/poc-lab/issues/14) の技術検証。国等が配布するExcel（原票）について、**様式を壊さずに、指定した入力セルだけへ値を書き戻せるか**を確かめた。この検証の時点では画面（UI）は作っていない。

> **この文書は #14 の検証記録です。** Web試作（#15）の使い方は [README.md](README.md) を参照。ここで検証した `src/` のコードは、Web試作でもそのまま使っている（ビルド時に `lib/` として配置）。検証用の道具・実測結果は GitHub Pages に公開しない。

背景と設計方針は [poc-docs の基本設計](https://github.com/YanTKYS/poc-docs/tree/main/proposals/inquiry-workflow)（`03-excel-integration.md`、`04-poc-plan.md`）。

## 判定（2026-11-17）

| 方式 | 判定 | 理由 |
|---|---|---|
| **B. 対象セルだけを書き換える（Open XMLを直接編集）** | **条件付き採用** | 2つの架空原票で、無変更往復は全部品が一致。62セルの書き戻しでも対象外の様式を保持。ブラウザ内でも同じ結果。**条件：Excel実機での確認が未実施** |
| A. 一般的なライブラリで読み書き（ExcelJS） | 不採用 | 原票の1つは読み込めず失敗。もう1つではシート保護・入力欄のロック解除・図形が失われた |
| P. openpyxl で読み書き（参考） | 不採用 | 図形が失われる。ブラウザで動かない |
| 代替案：セル番地と値の一覧を出力し、Excel上で流し込む | 未着手（予備） | 方式BがExcel実機で問題を起こした場合の退避先。今回は実装していない |

**後続の操作PoCは方式Bで進めてよいと判断する。ただし下の「未確認」を先に解消すること。**

### 数式セルの扱い（判断が必要な点）

方式Bは**数式そのもの（`<f>`）には触れない**。ただし既定では、値を1つでも書いたとき、**全シートの数式セルから「前回の計算結果」を取り除く**。

理由は実測による。計算結果を残したまま（`formulaResults: 'keep'`）LibreOfficeで開くと、「開いたときに再計算」の指定を入れていても**再計算されず、合計が古い値（0）のまま表示された**（`results/lo-check.json`）。計算結果を消しておくと、同じ環境で正しく再計算された。

| 設定 | 数式セルの変化 | LibreOfficeで開いた結果 |
|---|---|---|
| `'clear'`（既定） | 数式は同一。計算結果だけ消える | 合計などが正しく計算された |
| `'keep'` | 1バイトも変わらない | **古い合計（0）のまま** |

したがって「数式セルを書き換えない」は、**数式は書き換えない／保存済みの計算結果は消す**、が正確な答えになる。完全に無変更にもできるが、古い合計が残る危険の方が大きいと判断した。Excelは計算結果のない数式を開いたときに計算する想定だが、これも実機では未確認。

### 拒否する指定（1件でも当たれば何も出力しない）

| 指定 | エラー |
|---|---|
| 数式セル、配列数式の範囲内 | `E_FORMULA` |
| 結合セルの左上以外 | `E_MERGE` |
| 保護されたシートのロックされたセル | `E_LOCKED` |
| 存在しないシート／不正な番地／使用範囲の外 | `E_SHEET`／`E_REF`／`E_RANGE` |
| 日付書式でないセルへの日付 | `E_DATEFMT` |
| 数値でない値、存在しない日付、XMLに書けない制御文字 | `E_TYPE` |
| 同じセルの重複指定 | `E_DUP` |
| ZIPでないファイル（旧 .xls、暗号化されたブック） | `E_NOT_XLSX` |
| マクロ付きブック（.xlsm） | `E_MACRO` |
| 想定外のXML（接頭辞付き、コメント・CDATA入り、グラフシート） | `E_XML_SHAPE` |

## 比較した方式

| | A. 一般的なライブラリ（ExcelJS） | B. 対象セルだけ書き換え（採用） |
|---|---|---|
| しくみ | ブック全体を読み込んで内部モデルにし、全体を書き出す | ZIPを展開し、対象シートのXMLのうち対象セルの要素だけを文字列として置き換える |
| 触らない部分 | ライブラリが理解できた範囲だけ再現される | 1バイトも変わらない |
| 知らない要素（図形・拡張要素など） | 落ちる | そのまま残る |
| 実装量 | 呼び出すだけ（数十行） | 自前で約700行（`src/` の3ファイル）＋ZIPライブラリ |
| 保守 | ライブラリの更新・不具合に依存 | 自前コードの保守が必要。XMLの形の想定外は拒否する |
| ブラウザ | 動く | 動く（実測） |
| ライセンス | MIT | fflate は MIT。自前コードは依存なし |

方式Bの考え方は「**原票の作者（Excel）が書いたものを理解しようとしない**」こと。理解が必要なのは、セルの位置・数式の有無・結合・保護・書式番号だけに絞っている。

## 自動照合で保証できること／できないこと

`src/xlsx-verify.mjs` の `verifyWriteBack()` は、原票と出力を突き合わせて次を確かめる。

| 保証できる（ファイルの中身） | 保証できない（Excelで開いて人が確認する） |
|---|---|
| 部品の増減がない | Excelがエラーや「修復」なしで開けること |
| 変わった部品がワークシート・共有文字列・`workbook.xml` だけ | 画面上の見え方（表示形式の適用、折り返し、列幅に収まるか） |
| 変わったシートの**セル以外の部分がバイト一致**（結合・入力規則・保護・条件付き書式・列幅・図形への参照） | 再計算後の数式の結果、国側のエラーチェック欄の判定 |
| **行の属性（高さ・非表示・書式など）と行の並びが同じ**。増えてよいのは、書き込みのために足した行だけ。`spans` は書き込んだセルを含んでいる | 書いた値が**入力規則に合っているか**（規則外の値も書ける） |
| 対象外のセルは要素の文字列が同一。数式セルは数式と書式が同一 | 印刷結果、条件付き書式の見た目 |
| 対象セルは書式番号が同じで、値と型が期待どおり。セル内の並びは列の昇順 | 国の受付システムで受理されること |
| 共有文字列は元の項目が残り、末尾への追加だけ。**`count`（参照の総数）と `uniqueCount`（項目数）が、実際の増減と合っている** | |

ZIPファイル全体のバイト比較は成功条件にしていない（圧縮し直すため、中身が同じでも一致しない）。比較は展開後の部品単位と、セル単位で行っている。

## ブラウザ対応

**可。** `tools/browser-check.mjs` で、このフォルダを一時的なローカルサーバーから配信し、ヘッドレスChromiumで `src/` のコードをそのまま読み込んで62セルを書き戻した。

- 出力はNodeで実行した結果と**同じバイト列**（SHA-256一致）。照合も通過。
- 外部への通信は0件。処理時間は 6〜27ミリ秒。
- 必要なのは `src/` の3ファイル（計約34KB）と fflate（約91KB、同梱）。ビルド工程は不要で、import map か相対パスで読み込める。
- 利用者への受け渡しは `Blob` を作ってダウンロードさせる（Blobが作れることまで確認。ダウンロード操作は未実施）。

## 対象外の様式・できないこと

| 対象外 | 扱い |
|---|---|
| 旧形式（.xls）、マクロ付き（.xlsm）、開くのにパスワードが要るブック | 検出して拒否する |
| 行・列を追加する書き込み（行追加型の一覧表） | 機能を持たない |
| 数式セル・配列数式・結合セルの左上以外への書き込み | 拒否する |
| 接頭辞付きXMLなど、想定外の書き方をしたブック | 検出して拒否する（どの程度あるかは実物で要確認） |
| 書式付き文字列（一部だけ太字など）、時刻、真偽値 | 書けるのは数値・文字列・日付・空欄だけ |
| 入力規則に照らした値のチェック | していない。回答画面側か出力前確認で行う必要がある |

その他の制約：

- 文字列は、原票が共有文字列を使っていればそこへ入れ、使っていなければセル内に直接書く（原票の書き方に合わせる）。
  - 既存の項目（書式なしの単純な文字列）と同じ文字列は、新しい項目を作らずその番号を参照する。新しい文字列は末尾に追加し、同じ文字列は1項目にまとめる。
  - `count` は「文字列セルの参照の総数」なので、**既存の文字列セルを置換しても増えず、空欄・数値にすると減る**。`uniqueCount` は追加した項目の数だけ増やす。元の部品に属性がなければ足さない。
  - セルから参照されなくなった元の項目は、表に残る（Excelは許容する。保存し直すと消える）。
- 文書のプロパティ（最終更新者・更新日時）は原票のまま。
- 架空原票は**ライブラリが生成したもの**で、Excelが保存するファイルより単純である。Excel特有の要素（拡張要素、ふりがな、印刷設定の部品など）は含まれていない。

## 後続PoCへの引継ぎ

- **使うもの：** `src/xlsx-patch.mjs` の `patch(原票, 書き込み一覧, zip)`、`src/xlsx-verify.mjs` の `verifyWriteBack()`。書き込みは `{sheet, cell, type, value}`、`type` は `number`／`text`／`date`（`YYYY-MM-DD`）／`blank`。
- **出力前確認：** `patch()` が返す `errors` をそのまま画面に出せる。エラーがあれば出力は作られない。
- **出力直後の照合：** `verifyWriteBack()` の `problems` が空であることを確かめてから渡す。
- **「該当なし」の書き方**（文言か空欄か）は呼び出し側で決め、`text` か `blank` として渡す。
- **原票の読み取り：** `inspect()` でシート・保護・数式の数、`readAllCells()` で全セルの値が取れる。見出しの抽出に使える。
- **未実装で、次に要るもの：** 入力セル候補の検出に使う「塗りつぶし色」「入力規則」の読み取り（読むだけなので様式を壊す危険はない）、原票プレビュー用の列幅・結合の読み取り。
- **画面では数式を計算しない。** 出力したファイルの合計欄は、Excelで開くまで空である。
- **運用上の前提：** 提出前に必ずExcelで開いて確認し、上書き保存する（設計 `03` §5）。
